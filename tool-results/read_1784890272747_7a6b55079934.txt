     3→## Task ID: `multi-user-auth` — Multi-user authentication with role-based access
     4→
     5→**Date:** 2026-06-22
     6→**Scope:** Add admin/staff authentication, setup wizard, login page, user management UI, and per-user data isolation to the Reseller OS application.
     7→
     8→### Summary
     9→
    10→Extended the existing Reseller OS Next.js 16 app with a complete multi-user authentication system based on NextAuth.js v4. Two roles (admin and staff) are supported with strict data isolation per user and module-level access control. The application now requires login before any module access, with a setup wizard that appears on first launch to create the first admin account.
    11→
    12→### Steps implemented
    13→
    14→1. **Prisma schema (`prisma/schema.prisma`)** — Added a new `User` model (id, email, name, bcrypt password, role). Added an optional `userId` field and `user` relation to `StockItem`, `Sale`, `Supplier`, and `Expense`. `Attribute` stays global (shared between all users). Schema was pushed with `bun run db:push` (no migration files needed — SQLite). Existing rows have `userId = null`, which is acceptable.
    15→
    16→2. **bcryptjs dependency** — Installed `bcryptjs@3.0.3` (+ `@types/bcryptjs` dev dep) for password hashing.
    17→
    18→3. **NextAuth configuration:**
    19→   - `src/lib/auth.ts` — Credentials provider with bcrypt verification, JWT strategy, callbacks to inject `id` and `role` into the session, custom `signIn` page at `/login`.
    20→   - `src/app/api/auth/[...nextauth]/route.ts` — NextAuth route handler (`GET` + `POST`).
    21→   - `src/types/next-auth.d.ts` — TypeScript module augmentation to expose `id` and `role` on `Session.user` and `JWT`.
    22→   - Added `NEXTAUTH_SECRET` and `NEXTAUTH_URL` to `.env` to silence the `NO_SECRET` warning and enable JWT signing.
